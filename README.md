# CS 1.6 MOTD Builder

Визуальный конструктор HTML-страниц MOTD для Counter-Strike 1.6. Приложение работает в браузере, хранит настройки в LocalStorage и не требует backend.

## Локальный запуск

Нужен Node.js версии 20 или новее.

```sh
npm install
npm run dev
```

Сборка для публикации: `npm run build`. Просмотр production-сборки: `npm run preview`.

## Настройка способностей

Список способностей и значения по умолчанию находятся в `src/data/abilities.js`; они перенесены из предоставленного конфига без привязки к номерам ножей. Пустое значение у «Невидимости» означает, что параметры в исходном фрагменте не были заданы. В редакторе можно включать только нужные способности, менять флаг «Только с ножом» и отображаемые значения. Конструктор не задаёт и не реализует игровую механику.

## Cloudinary

Cloudinary настраивается владельцем сайта перед сборкой. Посетители могут загрузить изображение через настроенный unsigned preset или вставить внешнюю HTTPS-ссылку.

1. В панели Cloudinary откройте **Settings → Upload → Upload presets** и создайте preset с типом **Unsigned**.
2. Укажите `VITE_CLOUDINARY_CLOUD_NAME`, `VITE_CLOUDINARY_UPLOAD_PRESET` и `VITE_MOTD_STYLESHEET_URL` в локальном `.env` либо в GitHub Actions Variables.
3. Пересоберите и опубликуйте сайт. После этого посетители смогут выбрать файл (JPG, PNG или WEBP, до 3 МБ) и нажать «Загрузить».

Cloud name — это имя облака, указанное в консоли Cloudinary; это не имя пользователя, API key или API secret. Для unsigned preset желательно разрешить только нужные форматы. Название unsigned preset видно в клиентском приложении, поэтому не используйте его для загрузки конфиденциальных файлов. Размер до 3 МБ проверяется приложением перед загрузкой.

Локальные значения задаются в `.env` (образец — `.env.example`). Этот файл игнорируется Git. Переменные `VITE_*` встраиваются в клиентскую сборку, поэтому это публичные настройки, а не место для секретов. API key и API secret не используются.

Для GitHub Pages добавьте Actions Variables в **Settings → Secrets and variables → Actions → Variables** с именами `VITE_CLOUDINARY_CLOUD_NAME`, `VITE_CLOUDINARY_UPLOAD_PRESET` и `VITE_MOTD_STYLESHEET_URL`. Workflow передаст их в Vite-сборку. Если Cloudinary variables не заданы, загрузка отключена, но посетитель всё ещё может указать HTTPS-ссылку на картинку. Используется Unsigned Upload API; API key и API secret не нужны.

## GitHub Pages

1. Создайте GitHub-репозиторий и отправьте проект в ветку `main`.
2. В репозитории откройте **Settings → Pages** и выберите **GitHub Actions** как источник публикации.
3. Workflow `.github/workflows/deploy.yml` автоматически соберёт и опубликует сайт после push в `main`.

Vite получает имя репозитория из `GITHUB_REPOSITORY` в GitHub Actions и формирует подходящий `base` для GitHub Pages. Для локального запуска используется `/`.

## MOTD и совместимость

Экспорт создаёт HTML без JavaScript, внешних шрифтов и CSS-фреймворков; пользовательский текст экранируется. Изображения в HTML подключаются по HTTPS. Стандартный лимит — 1536 символов; его можно изменить в настройках. Разные сборки CS 1.6 могут иметь свои ограничения MOTD, поэтому проверьте экспорт на целевом сервере.

Доступны два шаблона: «Компактный» и «Таблица характеристик». Табличный шаблон показывает изображение, название, рейтинг, цену и только включённые способности с колонками наличия, применения только с ножом и дополнительного значения. Краткое описание используется только в компактном шаблоне. Значения и флаги способностей можно менять в редакторе; названия и описания находятся в `src/data/abilities.js`.

Оформление загружается из внешнего CSS по `VITE_MOTD_STYLESHEET_URL`; сам файл шаблонов расположен в `public/motd.css`. HTML содержит ссылку на стили, поэтому CSS должен быть опубликован по прямому HTTP или HTTPS URL, доступному игровому клиенту. Длина HTML зависит от текста, адреса картинки, ссылки на CSS и числа включённых способностей; если данные превышают лимит, приложение покажет фактическую длину и предупреждение, не обрезая документ.
